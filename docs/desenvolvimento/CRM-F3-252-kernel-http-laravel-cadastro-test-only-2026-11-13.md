# CRM F3-252 — Jornada HTTP real no kernel Laravel, exclusivamente em testes

A F3-252 aumenta o nível de integração: além dos CLIs F3-246–F3-251, agora o **kernel HTTP real do Laravel 13** processa requisições de uma jornada fictícia de emissão/verificação OTP e avaliação de trial por CNPJ. `SignupTrialHttpFixture` está exclusivamente em `tests/Support/` (autoload-dev) e as rotas `POST /__ci/f3-252/{operation}` são criadas exclusivamente no `setUp()` de `SignupTrialHttpFixtureFlowTest` sob PHPUnit, depois de subir uma aplicação de teste isolada. **Nenhuma rota é adicionada a `routes/`, a `bootstrap/` ou a `app/`.** A rota `/up` continua sendo a única publicada no CRM.

Os pedidos aceitos usam somente o marcador fixo `{"fixture":"synthetic"}`; a verificação também recebe `code` de exatamente seis dígitos, gerado internamente pelo Core para o cenário fictício. O código só pode ser obtido por método privado de teste, nunca por uma resposta HTTP, log ou envio. O fluxo passa pelo Core criptográfico verdadeiro (OTP, 900s, tentativa e replay somente process-local) e pelo sandbox de CNPJ alfanumérico (HMAC, marcador primeiro uso, duplicidade no mesmo processo). Testes verificam o resultado internamente, mas **todas as respostas HTTP têm status de demonstração, mensagens genéricas e flags de autorização `false`**; um usuário externo jamais recebe motivos distintos para código certo, errado ou reutilizado. Quaisquer campos adicionais (e-mail, CNPJ, tenant_id, telefones) ou conteúdo com CRLF são ignorados com a mesma resposta segura e sem efeitos.

O adaptador acrescenta cabeçalhos de segurança `Cache-Control: no-store`, `nosniff`, `X-Frame-Options: DENY`, CSP `default-src 'none'` e ausência de `Set-Cookie`. Testes verificam que `GET` não funciona nessa rota temporária, que `/signup` e `/api/signup` não existem no app real e que o código de fixture nunca foi incluído nos arquivos de rotas oficiais.

**Limitação:** é o kernel real com um router **registrado apenas durante testes**, não um endpoint Laravel de homologação implantado. Um OTP que coincide num sandbox não comprova posse do canal nem cria trial; os dois serviços são independentes, sem relação de confiança. Sem PostgreSQL persistente, autorização multitenant, sessões de verdade, SMTP/WhatsApp, conta, pagamento, migração ou VPS. Nenhuma permissão `ALLOW`. Para publicar a rota será preciso parecer SEG/DBA #27, CORE/LGPD #259, UX #416, garantia de transação única do lado do servidor, limites distribuídos, consentimento e validação de identidade. A PR pode integrar somente a DEV após 4/4 CI verde na SHA exata, mantendo `main`/produção sem alterações.
