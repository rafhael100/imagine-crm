# CRM F3-238 — modelo textual de OTP para WhatsApp, exclusivamente offline

A alternativa de receber um código de cadastro pelo WhatsApp existe como objetivo de produto, mas requer canal oficial, consentimento e **modelo utilitário aprovado pelo provedor**. Esta entrega cria `OfflineSignupOtpWhatsAppDraft`, um objeto de apresentação que gera, em memória e somente com código fictício de seis dígitos, um candidato textual em português do Brasil. A mensagem informa exatamente **15 minutos**, obtidos da constante `OfflineSignupOtpChallenge::VALIDITY_SECONDS=900` usada no e-mail da F3-236, com orientação para não compartilhar o código e ignorar envio não solicitado.

O placeholder genérico `{{1}}` é apenas uma proposta local; o projeto **não atribui nome, ID de template, integração Meta, credencial, número, destino ou aprovação real**. O resultado inclui texto com o código **somente na memória do teste**. Não serializar para cliente, logs, JSON de contrato, armazenamento ou telemetria. Todas as flags de provedor, aprovação, destinatário, LGPD, rate-limit, envio, fila, cadastro e autenticação permanecem falsas.

Os testes unitários verificam zeros à esquerda, seis dígitos, validade sincronizada, ausência de URLs e recusa de parâmetros maliciosos sem eco. **Não há chamada WhatsApp, SMS, e-mail, fila, HTTP, SQL ou cobrança**. Sem `main`, VPS ou produção. A homologação exigirá revisão de requisitos do provedor, verificação do telefone e contexto do pedido, política antiabuso, segurança dos tokens e aprovações SEG/DBA #27, CORE/LGPD #259 e UX #416. Merge apenas na DEV após revisão e os quatro workflows verdes.
