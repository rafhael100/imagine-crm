# CRM F3-242 — Prova integrada de antiabuso OTP na jornada fictícia

Este incremento integra `OfflineSignupOtpAbuseBudgetPreview` (F3-241) ao CLI determinístico de onboarding sintético já existente na F3-229/F3-235/F3-239. O CLI usa **o HMAC fictício de contato** produzido pela F3-234 e um HMAC separado para uma origem inventada. Todo snapshot de orçamento é construído na memória do processo sem contato com Redis, PostgreSQL, IP real, HTTP ou identidade.

O mesmo fluxo executa quatro cenários verificáveis: emissão fictícia dentro da janela ilustrativa, limite por contato (3 emissões simuladas), limite por origem (20) e limite de verificação (5 tentativas, coerente com `OfflineSignupOtpChallenge`). Os resultados são adicionados ao JSON de relatório como **quatro códigos de estado fixos**, com a flag `durable_otp_abuse_enforcement_verified=false`. Nenhum identificador HMAC, origem, e-mail, telefone, código OTP ou contador interno sai no JSON. Todos os direitos de cadastro/autenticação/envio continuam sempre falsos.

Esses limites são **somente propostas ilustrativas**, não uma política aprovada; um atacante poderia fornecer claims falsos. Uma futura implementação necessita de contador durável atômico, janela de expiração, agrupamento por identidade/canal/origem confiável, limites distribuídos, tratamento de proxies, auditabilidade, LGPD, proteção contra enumeração e critérios de revisão independente. Não há endpoint, usuário real, sessão ou envio via e-mail ou WhatsApp. Gates SEG/DBA #27, CORE/LGPD #259 e visual #416 continuam NO-GO. Merge apenas DEV com os quatro workflows verdes e diff revisado.

**Observação de segurança:** mensagens exibidas a usuários finais não devem revelar se um e-mail ou número já existe no CRM nem distinguir bloqueio individual de bloqueio por origem. Os códigos de observação desta demonstração são somente para testes offline; qualquer API futura precisa usar resposta pública genérica e budget atômico autenticado por servidor.
